# 숏폼 제작 Skill

## ⓪ 새 영상 요청이면 — 가장 먼저 방식을 묻는다 (생략 금지)

새 영상을 만들라는 요청에는 **어떤 문구든 제작·파일 작업 전에 먼저 이 질문 하나를 한다.** 요청에 "앱 소개"가 들어 있어도,
상황 제목이 들어 있어도 추측하지 않는다(AskUserQuestion, 단일 선택, 선택지 3개).

> 어떤 방식으로 만들까요?
> **1. 이야기** — 상황 제목 하나로 장면·자막·앱 알림 영상 (아래 1~4단계)
> **2. 모션 그래픽** — 앱 소개·장점을 키네틱 타이포 + 경쾌한 음악 박자 터짐으로 (아래 5절)
> **3. 새로운 방식** — 위 둘이 아닌 새 형태. 선택하면 어떤 형태인지 사용자에게 설명을 요청한다 (아래 6절)

- 이미 만든 한국어 편의 **다국어판·재렌더·번역 수정**만 요청한 경우는 묻지 않고 3단계로 간다.
- 방식이 정해져도 **실제 제작(파일 만들기·음원 받기·렌더) 전에 장면별 시나리오와 텍스트를 반드시 사용자에게 먼저 보여 주고 확인받는다.**
  이야기형은 1단계 표, 모션 그래픽형은 5절 표, 새로운 방식은 6절대로 보여 준다. 사용자가 고치라고 하면 표를 고쳐 다시 보여 주고,
  **"확인했다/진행해"라는 말이 있기 전에는 파일을 만들지 않는다.**
  (스킬이 시작됐다는 사실이나 "알아서 해줘"는 시나리오 확인이 아니다 — 확인 요청을 건너뛰지 않는다.)

---

제목(상황) 하나를 받아 **시나리오 → 한국어 영상 → 19개 언어 영상**을 만든다.
확인 지점이 세 번 있고, **사용자 확인 없이 다음 단계로 넘어가지 않는다.** 다국어 렌더는 오래 걸리고
저장소에 용량이 쌓이므로(편당 약 2MB × 20개 언어) 한국어에서 모든 수정을 끝낸 뒤 한 번만 돌린다.

```
1 시나리오 초안(한국어) ──▶ [확인①] ──▶ 2 한국어 영상 ──▶ [확인②] ──▶ 커밋·푸시(한국어)
                                                                        │
                           [확인③] ◀── 3 19개 언어 번역·렌더 ◀────────────┘
                              └──▶ 커밋·푸시(다국어)
```

## 1. 시나리오 초안 (한국어) → 확인①

### 먼저 — 이전 편과 문구가 겹치지 않게

지난 편의 문구는 `shorts.json`의 `langs.ko`에 전부 있다(따로 기록하지 않는다 — 두 벌이 되면 어긋난다).
초안을 쓰기 **전에** 제목·첫 자막·엔딩을 뽑아 본다:

```bash
cd ../averic-lab/_shorts-build && python3 -c "
import json,re;d=json.load(open('shorts.json'));k=d['langs']['ko']
for v in d['videos']:
  p=v['page'][0];f=lambda x:re.sub('<[^>]+>',' ',k.get(x,'(공통 엔딩)'))
  print(p,'|',k[v['title']],'|',f(p+'1'),'|',f(p+'_q1'),'/',f(p+'_q2'))
t=json.load(open('../i18n/translations.json'))['ko']['dawn_q3_html'];print('공통 엔딩:',re.sub('<[^>]+>',' ',t))"
```

- 판단 기준은 **단어가 아니라 뜻**이다. 첫 자막과 엔딩이 **이전 편과 같은 말을 하면 안 된다.**
  같은 단어가 들어가도 편의 핵심 주제가 다르면 괜찮다 — 예: "멀리"가 들어가도 주제가 *멀리 사는 가족*(E편)이
  아니라 *여행*이면 겹침이 아니다. 반대로 단어가 달라도 **상황·주제가 같으면** 겹침이다.
- **앱의 핵심 메시지는 겹쳐도 된다** — "안부는 전해집니다", "매일 자동으로 도착한다"처럼 이 앱이 하는 일을 말하는
  문장은 모든 편에 들어갈 수 있다. 바꿔야 하는 것은 **상황을 말하는 앞부분**이지 핵심 문장이 아니다
  (예: D편 "연락 한 번 못 하는 날에도 / 안부는 전해집니다." → 여행 편 "낯선 도시에서도 / 안부는 전해집니다.").
  ⚠️ **"안부는 전해집니다"를 피하려고 애쓰지 않는다** — "안부는 갑니다" 같은 대체 표현보다 공손하게 들린다.
  그대로 쓰는 것이 더 나으면 그대로 쓴다.
- 초안과 함께 **겹침 검사 결과**를 적는다 — 이 편의 핵심 주제(한 단어)와, 각 이전 편과 뜻이 어떻게 다른지.
- **공통 엔딩은 재사용해도 된다.** 홈페이지 `dawn_q3_html`("가족들은 늘 '난 괜찮아'라고 말합니다 …",
  gen.py 가 `q1`/`q2`로 나눈다)이 새 편의 이야기에 맞으면 `mountEnding(시작)`으로 그대로 쓴다.
  맞지 않을 때만 편 전용 엔딩을 새로 쓰고, 그때는 위 기준으로 이전 편 엔딩과 뜻이 겹치지 않게 한다.

아래 형식으로 **한 번에** 보여 준다. 자막은 편당 4~6개, 각 2줄 이내(한국어 한 줄 약 16자), 영상 20~27초.

```
#  화면                                   자막
1  <장면 — 공간·사물·빛으로>               -
2  (계속)                                 <자막>
…
엔딩(2줄, 한 문장이어도 됨)
<첫 줄>
<둘째 줄>
```

함께 적는다:
- **장면별 그림 구상** — 공간·사물·폰 불빛·앱 화면으로 상황을 보여준다. 인물의 표정 연기가 필요하면
  **고정 캐릭터**로만 그린다(README 「인물」 — 지금은 딸만 확정). 엄마·아들 등 다른 인물이 처음 필요한 편에서는
  딸 도면을 바탕으로 새로 다듬어 사용자 확인을 받은 뒤 README 표에 올린다. 멀리서 본 작은 사람은 지금처럼 얼굴 없이.
- **배경 연출** — 장면마다 **움직이는 디테일을 최소 하나** 정한다. 정지된 배경 위에 자막만 바뀌면 밋밋하다.
  예: 아파트 창문 불빛이 하나둘 켜진다 · 방 안으로 천천히 줌인 · 해가 지며 하늘색이 바뀐다 · 가로등이 켜진다 ·
  비행기가 하늘을 가로지른다 · 폰 화면 불빛이 방을 비춘다. 표에 `화면` 칸과 별도로 적는다.
- **효과음 계획** — 팝업·알림이 뜨는 장면만. 엔딩 로고 차임은 모든 편 공통.
- **걸음수** — 성인 5,000보 이상, 고령자 1천 보대(딱 1,000 피함). 7일치를 정한다.
- **이전 편과의 겹침 검사** — 위에서 뽑은 표와 대조한 결과.
- **번역 참고** — 직역하면 뜻이 바뀌는 표현(예: "~해지는 순간이 있다"는 becomes / there are moments).
- **앱 사실 검사 결과** — 아래 표로 하나씩 대조한 결과. 걸리는 게 있으면 고친 안을 같이 낸다.

### 앱 사실 검사 (시나리오가 앱과 다르면 광고가 거짓이 된다)

| 사실 | 시나리오에서 흔히 틀리는 곳 |
|---|---|
| 안부는 **연결된 보호자에게만** 간다. 코드를 주고받아야 연결된다 | "연락할 사람이 없다"로 끝나면 받을 사람이 없다 — "매일 연락하는 사람은 없다"처럼 고친다 |
| 안부는 **하루 한 번 자동** 전송된다(전화·앱 실행 불필요) | 대상자가 버튼을 눌러야 가는 것처럼 그리지 않는다 |
| **받는 쪽을 화면에 보여준다**("언니의 휴대폰" 같은 표시) | 누구에게 가는지 안 보이면 "누가 지켜본다"는 인상이 흐려진다 |
| 대등한 관계(연인·친구)는 **양방향**으로 보여준다 — 둘 다 G+S(보호자 겸 대상자)면 실제로 된다 | 한쪽만 확인하면 "감시"로 읽힌다 |
| 푸시 형식: `✅ 오늘 안부 확인 완료` / `별칭 · 오늘 N보를 걸으셨습니다.` | 문구를 지어내지 않는다(gen.py 가 서버·앱 번역에서 가져온다) |
| 응급 구조 앱이 아니다(긴급 도움 요청 버튼은 보호자에게 알릴 뿐) | 119·구조를 약속하지 않는다 |
| 긴급 도움 요청은 **도움이 필요할 때만** 쓴다 — 받는 쪽엔 🚨 긴급 알림(방해금지 무시)이 가고 대시보드가 긴급으로 바뀐다 | 약속 변경·장소 공유 같은 일상 연락에 쓰는 것처럼 그리지 않는다(오용을 가르치게 된다) |
| 안부는 전화·명절 인사를 **대신하지 않는다** — 전화와 전화 사이의 날들을 채운다 | "이제 전화 안 해도 된다"로 읽히게 그리지 않는다. 매일 여러 통씩 전화하는 과장된 장면도 피한다 |
| iOS 는 보호자 전용이지만 G+S 로 안부를 보낼 수 있다 | "아이폰은 안 된다"고 쓰지 않는다 |
| 특정 메신저·OS 화면을 흉내 내지 않는다 | 카카오톡 말풍선 색 등 |

**확인① 전에는 파일을 만들지 않는다.** 사용자가 고치라고 하면 표를 다시 낸다.

## 2. 한국어 영상 → 확인②

1. `shorts.json`
   - `videos`에 `{"id": "<kebab-case>", "page": "<다음 글자>.html", "title": "t_<글자>", "date": "<오늘>"}`
     — **`home`은 넣지 않는다**(홈 해질녘은 엄마·딸 두 편 고정).
   - `langs.ko`에 제목·자막·엔딩·이름 키(`<글자>1`, `<글자>_q1` …). 다른 언어는 3단계에서.
   - 앱 화면 문구가 새로 필요하면 `gen.py` `APP_KEYS`에 추가(20개 언어 dart 에 있는지 먼저 확인). 홈 추출 계약
     (`extract_strings.py` KEYS)은 건드리지 않는다.
2. 페이지(`<글자>.html`) — 가장 가까운 기존 편을 본떠 만든다. README 규칙 전부 적용:
   `setWeek([7일치])`, `window.SFX`(팝업마다 `t` = 그 요소의 `data-t`), `mountEnding(시작, L.x_q1, L.x_q2)`,
   엔딩이 한 문장이면 흐름 배치 덮어쓰기(`e.html` 참고).
   **배경 연출은 `window.extra = t => {…}`에서 시간 `t`의 함수로만 만든다**(`e.html`의 카메라 줌·창문 밝기 참고).
   CSS `animation`·`transition`·`setTimeout`은 쓰지 않는다 — 렌더가 `render(ms)`로 프레임을 하나씩 찍어서,
   시간에 묶이지 않은 움직임은 영상에 안 나오거나 프레임마다 어긋난다.
   - 여러 개가 켜질 때(창문 불빛)는 각자 시작 시각을 조금씩 다르게 준다 — 한꺼번에 켜지면 기계적으로 보인다.
   - 줌은 `transform-origin`을 보여 줄 대상(방·창문)에 맞추고, 배율은 1.0~1.2 안에서 천천히.
   - 배경 움직임은 **자막·푸시보다 눈에 덜 띄게** 한다. 자막이 뜨는 순간에 큰 움직임을 겹치지 않는다.
   - 배경 움직임에는 **효과음을 넣지 않는다**(효과음은 팝업에만 — README).
3. 검사 — **통과라고 말하기 전에 실제 값을 본다.**
   ```bash
   node render.mjs <글자>.html --check --lang ko
   node render.mjs <글자>.html --stills 1.5,5,9,13,17,22 $SP/st --lang ko   # 장면마다 → 이어 붙여 눈으로 확인
   ```
   요소 경계를 재서 아래 가림(768px)·오른쪽 가림(475px)·서로 겹침이 없는지 확인한다.
4. 렌더 — **그 편만**: `VIDEOS=<id> ./render_all.sh ko` (소리·검토 페이지·영상 페이지까지 자동).
   `audio.py` 보고에 `⚠`가 있으면 고친다.
5. 확인② — 장면 사진 한 장(이어 붙인 것)과 소리 보고를 보여 주고 파일 경로를 알려 준다. 사용자가 직접 듣는다.

확인②가 끝나면 한국어를 **커밋·푸시**한다(검토 페이지 + `/ko/shorts.html`에 나타난다).
⚠️ 확인받지 않은 영상 파일이 `media/shorts/`에 있는 채로 `i18n/build.py`를 돌려 커밋하면
공개 영상 페이지에 그 영상이 올라간다. 다른 작업을 커밋할 때는 미확인 영상을 잠시 옮겨 두고 빌드한다.

## 3. 19개 언어 → 확인③

1. 번역 — `shorts.json`의 19개 언어에 새 키를 넣는다. **먼저 `.claude/translation_glossary.md`를 읽고** 안부·대상자·보호자 용어와 금지어를 따른다. 한국어 영상의 **뜻과 톤**을 옮기되:
   - 이름은 **그 나라의 흔한 이름**, 호칭(언니·동생)은 그 언어의 자연스러운 관계어
   - 브랜드는 한국어만 "안부", 나머지는 "Anbu"
   - 1단계의 번역 참고를 지킨다 — 확인②까지 사용자와 확정한 번역 주의점은 **그 편을 끝낼 때 메모리
     `project_shorts_multilang_todo`의 "편별 번역 주의점"에 적어 둔다**(다국어는 며칠 뒤 다른 세션에서 돌 수 있다)
   - **번역 검증 절차는 모든 방식 공통이다**: 초안 → 애매한 문구는 해당 언어로 **인터넷 검색해 먼저 확인** → 그 결론을 **어드바이저에게 검증** → 반영. 사용자에게 번역을 어떻게 할지 묻지 않고 결과만 보고한다(자세한 절차는 5-4).
2. 렌더 — `VIDEOS=<id> ./render_all.sh`(언어 인자 없음 = 20개 언어).
3. 검사 — 전 언어 `--check`, 그리고 **독일어·러시아어**(문장이 길다), **아랍어**(좌우 반전), **태국어·힌디어**
   (글자 조합)는 가장 빽빽한 장면 정지 화면을 눈으로 본다.
4. 확인③ — 번역 요약(언어별 제목·이름)과 검사 결과를 보여 준다. 확인받으면 커밋·푸시.

## 4. 유튜브 전달 — 공유 드라이브 (한국어·다국어 각각 커밋·푸시 뒤)

유튜브 업로드·공개는 **공개 담당 LLM**이 맡는다. 이 스킬은 영상과 설명을 **공유 드라이브**로 넘기는 데까지만 한다.
규칙 전체는 `../averic-lab/_shorts-build/README.md` 「유튜브 전달」(여기에 옮겨 적지 않는다).

1. **upload.json 규칙은 파일 안 `_doc` 이 권위다**(2026-10-03 변경). `description` 은 **영상 내용 설명만 대략**
   (해시태그·설치 안내 없음 — 공개 담당이 SNS 에 맞게 다시 쓴다), `tags` 는 `[]`, `title` 은 임시 제목.
   앱 사실 검사 표는 설명에도 적용한다. 설명이 대략이라 사용자 확인 없이 넣어도 된다(사용자 지시 2026-10-04).
2. 확인받으면 mp4 를 `~/Library/CloudStorage/GoogleDrive-anbucheck1018@gmail.com/내 드라이브/안부 쇼츠/videos/<언어>/`에
   복사하고, 같은 폴더의 `upload.json`에 `"편id/언어"` 항목을 추가한다(기존 항목 형식을 따른다).
3. **`publish.json`은 읽기만 한다** — 공개 담당 전용. 거기 값이 있으면 그게 실제 유튜브 값이다.
4. ⚠️ 감사(audit) 전에는 **API로 업로드하지 않는다**(비공개로 고정된다). "유튜브에 올려 줘"라는 요청을 받으면
   감사 통과 여부부터 확인한다.

## 5. 모션 그래픽형 (⓪에서 "2"를 고른 경우)

앱의 장점·차이점을 **키네틱 타이포 + 앱 화면 조각 + 경쾌한 음악 박자에 맞춘 "빵빵" 터짐**으로 보여 주는 30~40초 영상.
첫 사례는 `h.html`(app-intro, 2026-10-02) — **구조·코드는 그 파일을 본뜨고, 규칙·교훈은 `README.md` 「앱 소개 모션 그래픽 편」에 있다**(여기에 옮겨 적지 않는다).

### 5-1. 시나리오 → 확인① (파일·음원 만들기 전)

소재는 홈페이지 한국어 문구(`i18n/translations.json` 의 `ko`: `hero_*`, `made*_h3`, `feat*`, `cta_lead_html`, `levels_*`, `help_*`)에서 가져온다 — 문구를 지어내지 않는다.
타사 앱을 이름으로 비교하지 않는다(범주 대비·암시만, 수위는 사용자에게 묻는다). 아래 표를 **한 번에** 보여 주고 확인받는다:

```
시간(박)   화면(앱 조각·도형)        자막                 애니메이션(어떤 박에 어떻게 터지는가)
```

- 길이·박 수: 가정 BPM(≈120)으로 1마디(4박)=약 2초. 드롭·재진입 같은 큰 터짐 위치를 표에 적는다(곡을 고른 뒤 실제 박으로 다시 산정한다고 알린다).
- 터짐 빈도: 매 마디 다운비트에 작은 터짐, 장면 전환·드롭에 큰 터짐(링 충격파 + 컨페티). 사용자가 더 자주 원하면 늘린다.
- 앱 사실 검사: 위 「앱 사실 검사」 표 전부 + **홈페이지 문구의 예외 조항을 같이 가져간다**(예: "멈추지 않아요"는 "폰 전원이 완전히 꺼진 경우 제외"를 작게 병기). 요금은 홈페이지처럼 "3개월 무료 체험, 이후 연 $9.99"를 함께 쓴다. 긴급 요청이 나오면 위치 1회·자정 삭제를 쓴다.
- 앱 화면은 지어내지 않는다 — 푸시는 실제 앱 알림(`✅ 오늘 안부 확인 완료`), OS 화면(배터리 사용량 알림 등)은 흉내 내지 않는다.

### 5-2. 제작 (확인① 후)

1. **음악**: Mixkit 무료 상업용(`media/bgm/LICENSE-증빙.md` 와 같은 라이선스)에서 100~128 BPM, 보컬 없는 곡 후보 3개를 받아 librosa(`pip install --target`)로 BPM·박 간격 안정성·에너지 구간(조용한 도입 → 드롭 → 브레이크)을 **측정**하고 하나를 고른다. 사용자가 못 듣는 곡을 추천할 때는 측정값을 근거로 든다. 원본은 `media/bgm/`(커밋 금지), 증빙 문서에 한 행 추가.
2. **곡이 타임라인이다**: 시간표를 초가 아니라 **박 번호**로 쓰고(`B = 60/BPM`), `bgm_start` 는 마디 경계, 곡의 드롭이 영상의 큰 전환과 맞게 정한다. 곡을 바꾸면 전부 다시 잰다. `shorts.json` 의 편에 `"audio": {"bgm": …, "bgm_start": …}` 로 그 편만 곡을 지정한다(`audio.py` 가 처리).
3. **효과음 없음**(음악 박자가 전부), 전체 -22 LUFS. 컨페티가 많아 화질은 페이지의 `window.CRF = 28`(저장소 사본 약 8MB).
4. 배경 연출·터짐은 시간 `t` 의 함수로만(`Math.random`·CSS animation·setTimeout 금지 — README 규칙). 장면이 늘어 곡 구조와 어긋나면 **박 번호 이동(`SH`)** 으로 푼다.

### 5-3. 검증 — "검사 OK"를 수치로 증명한다

- 기존 `--check` 는 이 영상의 새 클래스를 못 본다. **장면이 안착한 시점마다 요소 경계(위 77·아래 768·오른쪽 475)와 글자 겹침을 직접 잰다**(h.html 작업 때의 `layout.mjs` 방식: 박 단위로 `render()` 후 `getBoundingClientRect`). 전 언어에 돌린다.
- 소리 동기: 완성 mp4 의 저음 정점(드롭·재진입)과 영상 플래시의 시각 차를 수치로 보고한다(±1프레임 안).
- 썸네일: `render_all.sh` 의 1초 지점은 글자가 날아 들어오는 중간이라 지저분하다 → 안착한 장면(앱 알림이 뜬 순간 등)을 `ffmpeg -ss <초>` 로 **같은 파일명에 덮어쓴다**(재렌더하면 되돌아가니 다시).

### 5-4. 다국어 → 확인③

- **용어의 유일한 기준은 `.claude/translation_glossary.md`다 — 번역 전에 먼저 읽는다.** 그 다음 홈페이지 번역(`i18n/translations.json`)의 같은 뜻 문구에서 용어를 가져와 맞춘다(보내는 분/지켜보는 분, 안드로이드/아이폰, 20개 언어, 회원가입 없음 …). 비한국어는 브랜드 "Anbu".
- **가격 비교·관용 표현은 번역이 아니라 사실 주장이다** — "점심 한 끼 정도"처럼 가치를 비교하는 문구는 나라별로 **연 $9.99 와 비슷한 가격대의 현지 식사/물건**을 고르고 **웹 검색(Numbeo·환율 등)으로 가격대를 확인**한다(점심이 더 싼 나라에 "점심 한 끼"를 쓰면 과장). 개수 표현("한 끼, 두 끼")은 피한다.
- **번역 검증은 에이전트가 끝까지 처리한다 — 사용자에게 "번역을 어떻게 할까요/검수할까요"라고 묻지 않는다**(사용자는 그 언어들을 모른다). 순서:
  1. 번역 초안을 쓴다.
  2. **애매하거나 불안한 문구(뜻이 둘로 읽힘, 관용구인지 불확실, 가격·물가 같은 사실 주장, 약한 언어)는 해당 언어로 인터넷 검색해 먼저 확인**하고 결론을 낸다(WebSearch/WebFetch — 그 나라 언어 따옴표 검색, 현지 가격 자료 등).
  3. **그 최종 결론을 어드바이저에게 보여 검증**받는다(번역 문구 전체 + 검색으로 확인한 근거). 지적은 반영하고, 지적이 검색 결과와 충돌하면 근거를 대고 한 번 더 어드바이저에게 확인한다.
  4. 반영 후 렌더한다. 사용자에게는 **무엇을 바꿨고 무엇을 검색으로 확인했는지만 결과로 보고**한다.
  - 보고에는 이 검증이 원어민 검수가 아니라는 한계와 상대적으로 약한 언어(태국어·힌디어·베트남어·인도네시아어·아랍어)를 **사실대로 한 줄** 적는다 — 질문이 아니라 정보다.
- 글자 맞춤은 상자별 폭 기준(`FIT`)으로: 긴 언어(독일어·러시아어)·태국어·힌디어·아랍어 정지 화면을 눈으로 본다. 홈에 쓰는 편은 20개 언어 영상이 전부 있어야 홈에 나온다.

### 5-5. 유튜브 전달

저장소 사본(crf 28)은 유튜브가 다시 압축하면 화질이 두 번 깎인다 → **`CRF=18 node render.mjs …` 로 고화질 원본을 따로 렌더**하고 `.mix/<id>.m4a` 를 `-c copy` 로 붙여 공유 드라이브(4단계 규칙)에 둔다. 썸네일은 원본의 안착 프레임(1080×1920). `upload.json` 에는 `"편id/언어"` 항목을 20개 **초안**으로 쓴다(설명 규칙·긴급 요청 위치 문구 포함 — 4단계와 같다). 원본·`.mix/` 는 커밋하지 않는다.

## 6. 새로운 방식 (⓪에서 "3"을 고른 경우)

1. 사용자에게 **어떤 형태인지 설명을 요청한다**(목적·길이·표현 방식·음악·소재). 한 번에 묻는다.
2. 가장 가까운 기존 방식(1 또는 2)과 무엇이 다른지 정리해 확인받는다.
3. 위 ⓪의 **장면별 시나리오·텍스트 확인**을 거친다(표 형식은 그 형태에 맞게). 확인 전에는 파일을 만들지 않는다.
4. 공통 규칙은 그대로 적용한다 — 안전 영역, 앱 사실 검사, 소리 기준(`README.md`), 번역 검증, 커밋 규칙(음원 커밋 금지), 유튜브 전달.
5. 끝나면 **"이 방식을 스킬의 정식 방식(4번)으로 추가할까요?"** 를 묻고, 원하면 `README.md` 에 절을 쓰고 이 스킬의 ⓪ 선택지와 이 절을 갱신한다.
