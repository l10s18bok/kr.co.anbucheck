# 스토어 ASO — 언어별 키워드 재작성 (2026-10-11 시작)

**목표:** 한국어뿐 아니라 20개 언어 모두 현지 사용자가 실제로 검색하는 단어로 스토어 문구를 맞춘다. 앱을 **노출시키는 것이 우선**이다(노출 우선 정책 — 앱 저장소 `CLAUDE.md` 「노출 우선 문구 정책」: 불쾌·공포 표현도 심사 범위 안이면 쓰되 **다른 앱 이름·거짓 약속은 금지**).

## 파일 (먼저 읽는다)

- 현재 값·구조: 앱 저장소 `CLAUDE.md` 「스토어 등록 정보 폴더」. 로컬 파일은 **미리 고쳐 둔 값**이라 iOS 라이브 문구와 다른 것이 정상이다.
- `/Users/macmini/Documents/스토어 앱 등록 정보/안드로이드/<언어>.txt` — `[앱 이름]`(30) `[간단한 설명]`(80) `[자세한 설명]`(4000)
- `/Users/macmini/Documents/스토어 앱 등록 정보/ios/<언어>.txt` — `[앱 이름]`(30) `[부제]`(30) `[프로모션 텍스트]`(170) `[키워드]`(100, 헤더 형식 `(N자, M바이트 / 100자 제한)`) `[이 버전에서 업그레이드된 사항]` `[설명]`(4000)
- 번역 용어집 `.claude/translation_glossary.md` §1(검토 기준)·§2(언어별 용어)를 **언어를 시작하기 전에 읽는다.** 안부를 신호·health check로, 보호자를 법률 용어(후견인)로 옮기지 않는다.
- **진행표:** 같은 폴더 `progress.md`. 언어를 끝낼 때마다 갱신한다.

## 언어 하나의 절차 (앞 언어가 끝나기 전에 다음으로 넘어가지 않는다)

1. **Aside 조사 — 새 세션, 읽기 전용.** 프롬프트에 넣을 것: ① 읽기 전용(콘솔·로그인·설치·평점·파일 수정 금지) ② 우리 현재 문구(그 언어의 `ios/<언어>.txt`·`안드로이드/<언어>.txt`)를 읽어 기준선 파악 ③ **현지 검색어 목록** — 용어집 §2의 현지 "안부" 용어 + 독거/혼자 사는 사람/부모님·가족 확인/생존 확인/일일 체크인/고독사 등에 해당하는 현지 표현(Aside가 자동완성으로 검증·추가) ④ 앱스토어는 공개 iTunes Search API(`https://itunes.apple.com/search?term=<검색어>&country=<국가>&entity=software&limit=10`), 구글 플레이는 `https://play.google.com/store/search?q=<검색어>&c=apps&hl=<hl>&gl=<gl>`로 상위 10개, **우리 앱(`kr.co.anbucheck.live`)이 몇 위인지/안 나오는지** ⑤ 반복 상위 경쟁 앱 6~8개의 제목·부제/간단한 설명·설명 구조·키워드 반복 횟수 ⑥ 자동완성(수요 신호) ⑦ **유튜브 Studio 분석에서 나온 그 언어권 검색어**(있으면) ⑧ 결론: 상위 앱 표, 공통 패턴, 우리와의 차이, iOS(이름·부제·키워드 100자)·Play(제목 30·간단한 설명 80) 후보 2~3안(글자·바이트 수 포함), 확인하지 못한 것. 본 것과 추정한 것 구분.
2. **후보 작성(제가).** 검사: 용어집 금지어, 글자 수(바이트가 중요한 언어는 `len(text.encode())`도), iOS 키워드 규칙(이름·부제에 있는 단어는 키워드에서 뺀다, 쉼표 구분, 공백 없음, 복수형·중복 제거), Play는 키워드 나열·반복 금지(자연스러운 문장에 1~2회), Apple 2.3.7·Play 메타데이터 정책(다른 앱 이름·상표·순위·가격 문구 금지), 노출 우선 정책의 선. 한국어에서 추가한 `독거노인·생존확인·고독사예방`에 해당하는 현지어도 같은 위치(키워드 칸, 설명 문단)에 넣는다.
3. **사용자 승인.** 최종 키워드·이름·부제·간단한 설명과 근거(순위·자동완성)를 한 번에 보여 준다. **승인 전에는 파일을 고치지 않는다.**
4. **로컬 파일 수정** (한국어 때와 동일):
   - 먼저 `ios/_백업_YYYYMMDD/<언어>.txt`, `안드로이드/_백업_YYYYMMDD/<언어>.txt`에 수정 전 원본을 복사한다.
   - 정확 일치로 바꾼다(범위를 넓게 잡은 슬라이스 금지 — 2026-10-11 한국어에서 섹션을 지울 뻔했다).
   - 헤더의 `(N자 / M자 제한)`을 다시 센다(`len(body.strip())`). iOS `[키워드]` 헤더는 `(N자, M바이트 / 100자 제한)` 형식 — 따로 갱신한다. 모든 섹션이 제한 이내인지 확인한다.
   - 그 언어 파일만 바뀌었는지 확인한다(`find -mmin`).
5. **진행표 갱신 + 보고.** 바꾼 값 요약, 다음 언어 제안.

## 지켜야 할 것

- 한국어 한 언어만 보고 다른 언어에 옮기지 않는다 — 단어를 **직역하지 않는다.** 그 언어에서 실제로 검색되는지 자동완성으로 확인한다.
- 근거 없는 순위 요인은 "업계 통설(검증 안 됨)"로 표시한다. 적용 후 2~4주 순위 변화를 봐야 검증된다.
- 한 번에 여러 언어를 고치지 않는다(원인 추적 불가). 사용자가 묶으라고 하면 묶는다.
- iOS 라이브 문구는 로컬과 다르다 — 라이브 값이 필요하면 스토어를 직접 본다.
- Aside 세션 운영은 `aside-publish` 스킬 §2(새 세션/이어서 판단)와 `anbucheck-server/.ref/ASIDE-OPS.md` 4.1절을 따른다. 같은 언어의 후속(추가 질의·재조사)은 그 언어 세션에 `resume`한다.
